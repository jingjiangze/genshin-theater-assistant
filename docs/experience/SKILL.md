# 剧诗判断法（从真实视频蒸馏出来的操作规程）

> 本文件是**蒸馏产物**：每条规则都有实测来源（见 `SUMMARY.md` 与 `../../AUDIT-2026-11-05.md`）。
> 引用本文件时请同时引用对应数字，不要当成"通用经验"。

## 1. 先定位"我在哪"，再谈"该做什么"

判断顺序**固定**如下，任何一步命中就不再往下猜：

| 优先级 | 依据 | 命中后输出 |
|---|---|---|
| 1 | `actN` 模板（`templates/<宽>x<高>/actN.png`，阈值 **0.90**） | 第 N 幕 |
| 2 | 底部条带 OCR（纵向 `0.828–0.878h`，横向 `0.28–0.74`，放大 4×）且**恰好一个**「第N幕」 | 第 N 幕 |
| 3 | 整帧文字里的「第N幕」 | 第 N 幕（最弱，仅在没有 1/2 时用） |
| 4 | 菜单锚点（`难度选择/参演要求` → difficulty；`队伍配置/待命角色` → team） | 对应面板 |
| 5 | 以上都没有 | **不做判断**（见第 4 节"弃权"） |

**为什么条带要按行切**：实测 1080p 下幕次标签在 `0.852h`，而底部「第1幕…第10幕」列表在 `0.89–0.94h`。
把整条 0.82–0.96 一起 OCR，会同时读到多个幕次，取第一个就判错（真实评测准确率 **42.1%**）；
纵向切到 0.828–0.878h 后，同一批视频准确率 **100%**。

## 2. 时序：幕次只能往前走

- 正常推进（当前+1）或首次识别 → **立即采纳**；
- 倒退、跳级 → 需**连续 2 帧**观察到才采纳；
- 没观测到幕次 → **保持上一次**，不要闪回"未知"。
  （注意：判定"未观测"时不要清零候选计数，否则 `9, 漏, 9` 永远确认不了——这个 bug 被 CI 断言抓到过。）

## 3. 决策：能算出来就不要问人

有可选项时（买卡 / 三选一），输出必须是**可照做的指令**：

| 场景 | 指令 |
|---|---|
| 首领幕 3/6/8/10 | 选**本幕机制需要的元素**强化：3→雷、6→雷/水（破盾）、8→岩、10→水·治疗 |
| 非首领幕，或无对应强化 | 选**战斗卡补人** |
| 三选一，人数不足 | 「伙伴」 |
| 三选一，人数已满 | 「辉彩祝福」 |
| 选项原文有重名（如两张「战斗·普通」） | **按界面从左到右编号**，不要按名字去重 |

人数从界面文字读：`已额外编入4/4名待命角色`、`编入的角色数量 26`。

## 4. 弃权规则（比猜错更重要）

出现以下任一情况，输出「暂不判断」并说明原因，**不要给建议**：

- 幕次未知且没有任何面板锚点；
- 条带里出现 ≥2 个幕次（列表行）；
- 选项解析出 <2 个（多半是界面没打开或 OCR 漏读）；
- 大模型回答无法收敛到已有选项（只认「第N」或选项原文）。

## 5. 账号数据边界

- 允许：**只读本机游戏日志**里的角色字段（`avatarId` / `level`），映射用公开静态表 `data/characters-id.json`；
- 允许：用户自己提供的 `roster.json` / GOOD 导入；
- 不允许：登录态接口、读进程内存、注入、把账号数据外传。

  所以 `--log-scan` 只能先跑通链路，需用户启动一次游戏后再验证（PENDING）。
