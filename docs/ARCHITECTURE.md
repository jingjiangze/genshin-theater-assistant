# 架构定稿（2026-11-08，基于云端全流程重新审计）

> 本文件是**当前事实**，不是设想。每条都标注了验证方式与状态词：
> `PASS` 已被实测验证 / `PARTIAL` 部分验证 / `FAIL` 已知不成立 / `PENDING` 未验证。

## 1. 最终目标（唯一真源）

**让玩家「放空大脑只操作」：悬浮窗在正确时刻给出可立即执行的一步指示，且每个赛季、每位玩家都适配，同时不触碰封号红线。**

拆成五条可验收的目标：

| # | 目标 | 验收标准 | 现状 |
|---:|---|---|---|
| G1 | **给出可执行指示** | 任意一帧都有指示；选项出现时编号不越界；无依据时明确弃权 | `PASS` 决策编号 55/55、弃权 478/478（50 视频） |
| G2 | **每赛季自动适配** | 丢 `data/seasonNN.json` 即生效，不改代码/工作流 | `PARTIAL` 代码已数据驱动；已加 `--season-smoke` 造 season30 验证（本轮新增） |
| G3 | **每位玩家自适应** | 给 roster 就只从该玩家的角色里配队，并标注"玩家池" | `PASS` 已实测：玩家池 4 人 ∩ 本季 = 4，分配不越池 |
| G4 | **知识可信** | 只有 ≥2 独立作者 + 固定 holdout 通过才发布 | `PASS` verified=2 → release ACTIVE → 主仓 → 客户端可读 |
| G5 | **不违反封号红线** | 只读抓屏 + 离线 OCR + 自己窗口绘制；无注入/读内存/模拟输入 | `PASS` 代码层无 `OpenProcess/ReadProcessMemory/SendInput/SetWindowsHookEx` |

**不再追求的目标（明确划掉）**：
- ❌ 让模型决定机制事实（模型只做措辞/随机要素裁决）
- ❌ 视频帧上计算"幕次准确率"（底部条带会命中 UP 主字幕，指标无效，已改为只在单幕次帧计）
- ❌ 真机验收（用户明确不需要）

## 2. 分层架构

```
┌─ L1 输入层（只读）──────────────────────────────────────────────┐
│ GDI 抓屏（自己进程内）→ 帧                                          │
│ 红线：不 OpenProcess / 不 ReadProcessMemory / 不 SendInput          │
└──────────────────────────────┬───────────────────────────────┘
                               ↓
┌─ L2 识别层（确定性）───────────────────────────────────────────┐
│ 模板匹配 actN/diff/hall  条带 OCR(0.828–0.878h)  OCR 文本         │
│ ActStabilizer：+1 立即、倒退/跳级需连续确认；连续 3 帧未识别→弃权    │
└──────────────────────────────┬───────────────────────────────┘
                               ↓
┌─ L3 数据层（全部来自 data/，代码不硬编码决策内容）────────────────┐
│ seasonNN.json     敌人等级/波次/抗性 → 需求向量（只收本季元素）      │
│ act-playbook.json 每幕机制/时间窗/该做什么                          │
│ decision-policy.json 难度权重/触发词/覆盖率/置信度/别名             │
│ characters+substitutes 元素与职能（多职能 + 别名归一）              │
│ roster.json（可选）玩家真实池 → 个性化                              │
│ knowledge-release.json 云端已验证知识（★）                          │
└──────────────────────────────┬───────────────────────────────┘
                               ↓
┌─ L4 决策层（可解释）───────────────────────────────────────────┐
│ ① 量化：需求向量 × 池覆盖 → 分数+置信度（◆）                        │
│ ② 配队：C(n,4) 完全枚举；跨幕全局分配（同难度内角色不重复）           │
│ ③ 编排：◇模型 处理随机要素(buff/三选一) → ★已验证 → ○语料 → ·规则    │
│ 每行输出都带来源标记与"随机点"，缺口如实列出                          │
└──────────────────────────────┬───────────────────────────────┘
                               ↓
┌─ L5 呈现层（Windows 悬浮窗）───────────────────────────────────┐
│ 无激活透明窗 + SetWindowDisplayAffinity(0x11)；语音可选            │
└───────────────────────────────────────────────────────────────┘

┌─ L6 自动化层（云端 + Actions）─────────────────────────────────┐
│ GitHub Actions：video-ingest → knowledge-extract → verify → release│
│                 season-plan（逐赛季 team-plans/global-alloc）       │
│ Simular box（Ubuntu）：跨平台 CLI 全流程 + 每 600s 持续回归         │
└───────────────────────────────────────────────────────────────┘
```

## 3. 职责边界（谁不许做什么）

| 组件 | 必须做 | 绝对不做 |
|---|---|---|
| 识别层 | 给幕次/界面/选项/编队 | 猜机制、猜对策 |
| `data/*.json` | 承载**所有**决策内容 | 承载凭据 |
| 量化/配队 | 可复现的枚举与打分 | 联网、读环境、写知识 |
| 编排器 | 保证永远有指示 + 标来源 | 把模型输出当事实写库 |
| 模型（◇） | 措辞、随机要素裁决 | 决定机制真伪、生成知识 |
| `verify_candidates` | 只按固定 holdout 晋级 | 放宽阈值迎合数据 |
| 云端 loop | 回归 + 冒烟 + 探针 | 部署、写生产数据 |

## 4. 单一真源（本轮修掉的分裂）

| 概念 | 唯一来源 | 曾经的错误 |
|---|---|---|
| 角色池 | `TeamSolver.LoadPool` | `QuantScorer` 用 `GenericTeam` → 同一幕"评分说缺 Electro、配队却有 Electro 队"（本轮统一） |

| 已验证知识 | `data/knowledge-release.json`（由 ledger release 生成） | 曾由代码内联文案承担 |

## 7. 已知缺口（不粉饰）

1. **B站/YouTube 采集依赖 Actions + cookie**，云端 box 未跑过（无 cookie）。
2. **跨作者证据仍稀缺**：verified=2；`第2幕 推荐 夜兰` 策略成功率与基线持平（1.00 vs 1.00），只能算"不劣"。
3. **buff 出现率未建模**：按用户决定交模型，不做概率。
4. **BetterGI 的 OCR/识别实现尚未对齐**（用户明确要求"照抄这个的实现"）→ 下一轮首要技术项。
5. **第二赛季冒烟是合成数据**，不是真实新赛季。
