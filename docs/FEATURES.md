## 一、总体架构

```
┌─────────────── 玩家 Windows（单文件 exe，离线可用，~100MB）────────────────┐
│                                                                          │
│  ┌─ L1 只读输入 ─────────────┐                                            │
│  │ GDI 抓屏（本进程内）       │  ✗ 不 OpenProcess / ReadProcessMemory        │
│  │                           │  ✗ 不 SendInput / keybd_event / SetWindowsHookEx │
│  └──────────────┬────────────┘                                            │
│                 ▼                                                          │
│  ┌─ L2 识别（确定性）────────────────────────────────────────────────┐    │
│  │ 模板匹配 actN/diff/hall       底部条带 OCR（0.828–0.878h）          │    │
│  │ 全帧 OCR：RapidOcrNet PP-OCRv6  → 透视裁剪+竖排旋转（库内已实现）    │    │
│  │ OcrTextPipeline：DropScore 过滤 + 同排按 X 排序（防"第N张"错位）    │    │
│  │ ActStabilizer：前进立即采纳 / 倒退跳级需连续确认 / 连续3帧未识别→弃权 │    │
│  └──────────────────────────────┬───────────────────────────────────┘    │
│                                 ▼                                        │
│  ┌─ L3 数据层（决策内容全部在 data/，代码不硬编码）──────────────────┐    │
│  │ seasonNN.json        敌人等级/波次/抗性 → 需求向量（只收本季元素）   │    │
│  │ act-playbook.json    每幕机制/时间窗/该做什么                      │    │
│  │ decision-policy.json 难度权重·幕权重(boss×1.5)·触发词·置信度·别名   │    │
│  │ characters + substitutes  元素/职能（多职能 + 别名归一）            │    │
│  │ rotations.json       社区推荐 communityRecommended                 │    │
│  │ knowledge-release.json 云端已验证知识（VERIFIED，2 条）             │    │
│  │ roster.json（可选）   玩家真实池 → 个性化                           │    │
│  └──────────────────────────────┬───────────────────────────────────┘    │
│                                 ▼                                        │
│  ┌─ L4 决策层 ──────────────────────────────────────────────────────┐    │
│  │ QuantData          敌人档案 → Need[] 需求向量                     │    │
│  │ QuantScorer        需求×覆盖 → 分数+置信度+缺口   [Q1–Q6 自洽判据] │    │
│  │ TeamSolver         C(n,4) 完全枚举 → 逐幕最优 4 人 [G1–G7 闸门]    │    │
│  │ GlobalAllocator    跨幕分配：同难度内不重复 + 治疗/破盾硬约束        │    │
│  │                    + 幕权重（boss×1.5 / level 归一）               │    │
│  │ CuratedPicks       幕级推荐（社区共识 + 已验证）→ 选人加权          │    │
│  │ DecisionOrchestrator 三级兜底：                                    │    │
│  │                    ◆量化 → ◇模型 → ★已验证 → ○语料 → ·规则         │    │
│  └──────────────────────────────┬───────────────────────────────────┘    │
│                                 ▼                                        │
│  ┌─ L5 呈现 ───────────────────────────────────────────────────────┐    │
│  │ 悬浮窗：无激活 + 透明 + 防截屏检测（SetWindowDisplayAffinity）     │    │
│  │ 每行带来源标记与"随机点"；语音可选                                 │    │
│  └─────────────────────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────────────────────────┘

┌───────────────────── 自动化层（全自动，无人工审批）─────────────────────┐
│  GitHub Actions（Windows）             云端 box（Linux）                 │
│  ├ ci：134 断言 + 渲染 7 + 真机 8      ├ cloud-all.sh：18 步全流程       │
│  ├ video-ingest → 采集视频文本          ├ cloud-ocr.sh：v5/v6 交叉验证    │
│  ├ knowledge-extract → 候选/证据        ├ OcrProbe：模型实验（--by-kind） │
│  ├ verify_candidates → 固定 holdout     └ linux-loop.sh：每 900s 回归     │
│  ├ auto-release → release+active+回滚                                   │
│  └ season-plan → 逐赛季配队产出                                          │
│         │ 写权唯一                              │ 只读                   │
│         ▼                                       ▼                       │
│  automation-data 分支（不可变账本：批次 / 证据 / 候选 / release / active）│
└──────────────────────────────────────────────────────────────────────────┘

沟通约束（本机 github.com:443 不通）：所有提交走 gh-commit/sync-to-github（Contents API）
```
